The problem

The plant was missing its output targets. My goal was to find which part of the production system was limiting throughput and recommend what plant leadership should do about it.

Data & tools

Five raw CSV files covering September 2025 to February 2026: production, labor, downtime, shift, and workstation data for six workstations. I cleaned them and built a relational data model in Power BI, plus a Date table.

What I did

  • Wrote DAX measures for Unit Target %, Scrap Rate, Downtime %, OEE and its three parts (availability, performance, quality), Units per Labor Hour, and a measure that finds the lowest-OEE workstation.
  • Built a one-page interactive dashboard with KPI cards, output vs. downtime by workstation, downtime by cause, a monthly target trend, a shift comparison, and an OEE breakdown table.
  • Wrote a one-page executive summary with findings and recommendations for plant leadership.
  • Revisited the model after the course: corrected the downtime measure to count scheduled time on both shifts, and added the OEE breakdown.

Key DAX measures

Three of the measures behind the dashboard, copied from the Power BI file.

Downtime % of scheduled time

Each production row is one workstation on one 8-hour shift, so scheduled minutes are the row count times 480. Downtime is measured against that.

Scheduled_Min = COUNTROWS ( ProductionData ) * 480

Downtime % = DIVIDE ( [Total_Downtime_Min], [Scheduled_Min] )

OEE from its three parts

Availability is run time over scheduled time. Performance compares the ideal run time at each station's standard cycle time with the time it actually ran. Quality is good units over total units. OEE multiplies the three, which shows why a station is behind, not just that it is.

Availability = DIVIDE ( [Scheduled_Min] - [Total_Downtime_Min], [Scheduled_Min] )

Performance =
DIVIDE (
    SUMX (
        ProductionData,
        ProductionData[Units_Produced]
            * RELATED ( WorkstationInfo[Standard_Cycle_Time_Seconds] )
    ) / 60,
    [Scheduled_Min] - [Total_Downtime_Min]
)

Quality = DIVIDE ( SUM ( ProductionData[Good_Units] ), [Total_Units_Produced] )

OEE = [Availability] * [Performance] * [Quality]

Finding the bottleneck automatically

Scores every workstation's OEE in the current filter context and returns the lowest, so the KPI card names the constraint on its own and updates when you filter by shift.

Lowest OEE Station =
VAR t = ADDCOLUMNS ( VALUES ( WorkstationInfo[Process_Name] ), "@oee", [OEE] )
VAR worst = TOPN ( 1, t, [@oee], ASC )
RETURN MAXX ( worst, WorkstationInfo[Process_Name] & ": " & FORMAT ( [@oee], "0.0%" ) )

Findings

  • Drilling was the bottleneck, reaching 83.9% of its unit target while the other workstations ranged from 95.2% to 104.0%. It was the lowest station in every month and on both shifts, so the gap was systemic, not a one-time disruption.
  • Scrap was ruled out: 1.9% at Drilling vs. 1.2–1.5% elsewhere is far too small to explain the gap.
  • The main cause was downtime. Drilling was down 14.9% of its scheduled time, compared with 9.3% at Inspection, the next highest. Machine faults were the largest cause, at 2.6 times the machine-fault downtime of the next-highest station, and material-shortage downtime was more than four times any other station's.
  • Slower cycles were a second factor. Drilling's cycles averaged 56.1 seconds against a 52-second standard, about 8% slow, while every other station ran within 2% of standard.
  • OEE put it in one number: 75.4% at Drilling, the lowest in the plant (85.7–93.5% elsewhere), with availability at 85.1%, performance at 90.3%, and quality at 98.1%.

Recommendations

  • Start a preventive maintenance program for the Drilling equipment.
  • Run a formal inspection to decide between repairing and replacing it.
  • Improve material availability at Drilling to cut shortage downtime.

What I learned

Test the obvious explanation before acting on it. Drilling had the highest scrap rate, which made quality the easy guess, but the numbers pointed to availability instead.
